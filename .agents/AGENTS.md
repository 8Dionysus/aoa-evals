# AGENTS.md

## Applies to

`.agents/` agent-facing lanes and companion guidance.

## Role

`.agents/` holds local agent-facing route guidance for `aoa-evals`.
The former Spark lane is retired; no active lane is declared here.

It routes agents to the task's source bundle and proof doctrine. Generated
readers, runtime state and receipts remain with their named owners and do not
replace source proof authority.

## Operating Card

| Field | Route |
| --- | --- |
| role | local agent-facing route district |
| input | local route guidance and proof-surface route pressure |
| output | scoped agent route or handoff toward the proof owner |
| owner | `.agents/AGENTS.md` for lane placement; lane-local `AGENTS.md` for local posture |
| next route | the exact proof owner surface, or top-level `skills/` for the admitted callable proof procedure |
| tools | root validation, semantic AGENTS validation, nested AGENTS validation |
| validation | this card's `Validation` section |

The admitted `aoa-evals-skills` bundle is exposed once through the OS user profile;
it is not copied into this district.

## Owner Routes

- A future lane under `.agents/<lane>/` needs an actual local responsibility; do not recreate the
  retired Spark scaffold merely to fill this district.
- Keep an owner-admitted repository skill's canonical source under top-level
  `skills/`, never under `.agents/`.
- Do not recreate owner or shared skill copies below `.agents/skills`; the OS
  user profile is the only active Codex exposure for this owner bundle.

| Need | Owner route |
| --- | --- |
| bundle proof meaning | bundle-local `EVAL.md` and `eval.yaml` |
| generated reader updates | `generated/AGENTS.md` and the owning builder |
| receipt authority | publication-receipts mechanic or bundle-local report surface |
| runtime authority | runtime owner or audit intake route |
| sibling-owner truth | owning sibling repository |
| repo doctrine or topology | root/docs source surfaces |

Local route guidance stays below bounded proof claims. Public-safe wording is
the standard; private logs, hidden benchmark data, and host-local secrets
stay outside checked-in agent lanes.
